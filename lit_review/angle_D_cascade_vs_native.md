# Angle D: Cascade (ASR + text LLM) vs audio-native speech LLMs, and audio-LLM behaviour on spoken entities

Scope note: this file maps the PIPELINE-COMPARISON line (cascaded ASR->LLM versus end-to-end
speech/audio LLMs on downstream tasks) and the behaviour of audio LLMs as transcribers and
entity readers. This is prior work we delineate, not claim. Our candidate contribution is
elsewhere: a SILENT-WRONG ledger for spoken-entity tool calls (schema-valid, executed, wrong
semantics, no question asked) across three pipelines (local Whisper -> text LLM; audio LLM as
transcriber -> text LLM; audio-native LLM calling tools), crossed with acoustic conditions
(voices per accent, rate, noise, 8 kHz telephone), with read-back confirmation measured as a
recovery lever against confidence gating and an ask-when-unsure instruction. None of the
papers below measure that ledger; the closest neighbours are flagged at the bottom.

Verification: all ids resolved and abstracts fetched live on 2026-09-24 via the Semantic
Scholar Graph API batch endpoint (`/graph/v1/paper/batch`, keyed by `ARXIV:<id>`), after
the arXiv export API (`export.arxiv.org/api/query`) returned HTTP 429 on every attempt

batch returned 37/37 entries with non-empty abstracts. "What it established" lines are

## Notes

- **Pre-emption assessment for angle D: no verified paper measures a silent-wrong ledger for
  spoken-entity tool calls across cascade vs audio-native pipelines, nor a confirmation
  lever's recovery.** The field has (i) many cascade-vs-end-to-end benchmarks on QA,
  translation, math and instruction following, with a consistent "cascade is more robust,
  native is closing" story (2410.17196, 2512.16378, 2508.21376); (ii) a 2025-2026 line of
  spoken tool-calling benchmarks that report aggregate parameter/argument accuracy and note
  that argument values are the dominant loss (2510.07978, 2605.15104, 2609.20152,
  2604.22821); (iii) DST work stating that ASR errors concentrate in entity values
  (2609.01828). None classify a wrong-argument call as executed-without-error vs surfaced vs
  asked, none cross entity type x acoustic condition x pipeline, and none measure read-back
  confirmation, confidence gating, or ask-when-unsure as recovery levers with an oracle.
- **Unverified / non-arXiv items seen in search:** "BFCL Audio: A Benchmark for Audio-Native
  Function Calling" (Salesforce AI Research + Berkeley, blog, Aug 2025). Web-visible
  description: existing BFCL queries rewritten to conversational speech and synthesised with
  several TTS engines; end-to-end models take audio, cascaded models get transcripts from
  three ASR systems (OpenAI, ElevenLabs, Deepgram) to expose ASR sensitivity; scored by AST
  match. No arXiv id found, so no abstract verified. This is a NEAR neighbour on the
  cascade-vs-native tool-argument axis and MUST be read from the blog and leaderboard before
  CP2; if it reports per-argument error by ASR choice, cite it as the closest prior
  measurement and delineate on the silent-wrong ledger, acoustic conditions and levers.
- Also verified but not tabled (weaker fit): 2509.03526 (Reinforced Behavior Alignment,
  training for consistency across speakers/accents/noise), 2603.07025 (language-aware
  distillation with a Whisper cascade baseline), 2410.16130 (sound-event hallucination
  tasks), 2506.04779 (MMSU, paralinguistic SLU), 2509.04473 (SpeechLLM adapter incl. spoken
  NER), 2605.27984 (Korean SpeechLM benchmarks), 2608.28875 (prompt-context ablation on
  gpt-4o-transcribe and gemini-2.5-flash, notes Gemini worsens unlisted-token error).
- Year caveat: S2 publication dates are used; arXiv ids 26xx imply 2026 and agree in all
  cases here.
- Delineation sentence for the paper: that end-to-end speech LLMs trail or match ASR+LLM
  cascades depending on task and acoustics is established (VoiceBench 2410.17196, Hearing to
  Translate 2512.16378, AHELM 2508.21376); that spoken tool calling loses accuracy mostly in
  argument values is reported by VoiceAgentBench (2510.07978), From Text to Voice
  (2605.15104) and MTVA-Bench (2609.20152); that ASR errors concentrate in entity values is
  stated for spoken DST (AVERT 2609.01828). What is new in our work is the ledger: how often
  a mis-heard entity becomes a schema-valid, executed call with no error and no question,
  by entity type, pipeline and acoustic condition, and how much of that cell a read-back
  confirmation recovers against confidence gating and an instruction alone.
